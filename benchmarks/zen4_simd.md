# Ryzen 7 PRO 8840U：SIMD 实测与优化

日期：2026-09-08。基线为 `2f25f15`（3.6.0），对比 3.6.1 中的 SIMD 优化（性能测量时版本号仍为 3.6.0）。两边都已经包含此前的共性加载优化和 SIMD 实现；下面不是与纯标量旧版本相比。

## 环境与测量方法

- 实机 AMD Ryzen 7 PRO 8840U，8 核 / 16 线程；确认 AVX2、AVX-512F/DQ/BW/VL 可用。
- Ubuntu 20.04，Linux 5.15.0-67，glibc 2.31，GCC 9.4.0。
- uv 0.11.25 创建的隔离环境，CPython 3.14.6、NumPy 2.5.3、SciPy 1.18.1、Cython 3.3.0。安装依赖通过跳板机代理完成，未修改系统 Python 或设备网络设置。
- 扩展采用相同的 Python 默认 `-O3` 编译参数；不使用 `-march=native`、`-ffast-math` 或额外 FMA 融合。AVX2 对照在原始 CFLAGS 上追加 `-DWF_DISABLE_AVX512`，没有替换掉优化级别。
- 测量进程固定在逻辑 CPU 2，未修改原有 performance governor 或 boost 设置。这是单核测量，不代表多通道满负荷运行。
- 独立进程顺序为 A/B、B/A、A/B。设备流程每项自适应循环、重复 11 次取中位数，再取三轮中位数。百万点 Python API 测试沿用原脚本：每轮取 11 次最小值，再取三轮中位数。两类统计口径不混用。
- 栈基准使用 2.4 GHz、最终校准右移 2 ns，覆盖全部事件范围。`cold` 每次重新反序列化、shift、建立计划、首次采样；`warm` 复用计划。场景是代表编译器输出的合成事件栈，不包含外部 qlispc 编译、网络传输或仪器下发时间。
- 原始三轮数据、源码 SHA-256、误差核对和内核探针保存在 `zen4_simd_results.json`。比较脚本为 `analyze_device_simd.py`。

## 保留的改动

1. **AVX-512 量化**：消除逐批有限性掩码的串行依赖。GCC 9 原先生成了跨迭代的 mask → 通用寄存器 → mask 链；改成独立检查后可并行推进批次。同时直接转换为 int32，省去中间 int64。
2. **三次非线性映射**：AVX2 / AVX-512 连续载入每个区间的四个系数，再转置到 SIMD 通道，代替四次 gather。运行时及序列化布局不变，Horner 运算顺序不变。
3. **栈内批量量化**：重复幅值模板一次批量量化后复制；大量不同幅值事件使用 256 点暂存块完成缩放、限幅和 SIMD 转换，不再逐点调用标量 round，也不分配整段浮点输出。保留重叠波形先累加、再限幅和量化的顺序。
4. **DRAG 向量求值与冷计划**：批量计算包络和载波三角函数；Linux 使用已有 libmvec 分派，macOS 使用 Accelerate。至少 32 点的 DRAG 模板在建计划时接入此路径。短模板、未支持节点、分配失败仍可回退标量；时间坐标保持原 long double 算法。
5. **隔离模板求值代码**：不让新增向量 / 标量求值分支内联进每事件的计划建立循环，收敛非 DRAG 场景的回退。
6. **半 LSB 边界修正**：修正 x86 SIMD 中紧邻 ±0.5 LSB 的数因加法舍入而被错误进位的问题；精确半 LSB 仍向远离零的方向取整。

运行时继续按 CPU 能力分派；没有给所有机器强制 AVX-512，也没有增加面向某个 CPU 型号的配置项。

不宣称全面提升：重复模板的纯采样已主要在初始化和复制输出，int16 基本持平；密集 / 稀疏 flux 的部分冷采样中位数仍慢约 2%–6%。这些场景的 float64 热采样 `out` 基本持平，冷采样各轮也存在波动，不能把小差异都归因于 SIMD 算术。

## 百万点内核与 Python API

独立 C 探针每批在 C 内循环，七次中位数，避免短批次的 Python 调用开销。单位 ns/点。

| 内核 | 修改前 | 修改后 | 倍率 |
| --- | ---: | ---: | ---: |
| AVX-512 int16 量化 | 0.3872 | 0.1621 | 2.39× |
| AVX-512 int32 量化 | 0.4083 | 0.1665 | 2.45× |
| AVX2 三次映射，4097 点表、平滑输入 | 1.8663 | 1.3983 | 1.33× |
| AVX-512 三次映射，同上 | 2.2698 | 1.2176 | 1.86× |
| AVX-512 三次映射，4097 点表、随机输入 | 2.5281 | 1.3106 | 1.93× |

最终 AVX2 量化约 0.2093 / 0.1906 ns/点，AVX-512 已比它快，因此不保留“在 Zen 4 全局禁用 AVX-512”的方案。线性插值没有专门改写，不把它的小幅变化计作确定收益。

包含 Python 封装和输出分配的百万点 API 耗时（ms）：

| 操作 | 修改前 | 修改后 | 倍率 |
| --- | ---: | ---: | ---: |
| quantize int16 | 0.4524 | 0.3296 | 1.37× |
| quantize int32 | 0.4749 | 0.3936 | 1.21× |
| 三次映射 float64 | 2.3756 | 1.3467 | 1.76× |
| 三次映射直接 int16 | 2.6556 | 1.4290 | 1.86× |
| 波形采样＋三次映射＋int16 | 5.3530 | 4.0677 | 1.32× |

单独把 double → int64 → int32 改成 double → int32 的第一轮候选并未让量化变快；移除掩码依赖后才有稳定收益。原始中间候选探针也保留在 JSON 中。

## 反序列化、体积与正确性

解码逻辑和二进制格式均未改动。1 万事件 native 解码约 0.042 ms，1000 个不同 DRAG 模板约 0.217 ms，前后基本相同；不要把首次采样加速解释为反序列化加速。

| 场景 | 原生块字节数 | pickle 字节数 |
| --- | ---: | ---: |
| 1000 DRAG，重复模板 | 20,168 | 20,290 |
| 1000 DRAG，不同模板 | 172,016 | 172,147 |
| 1 万 flux，密集或稀疏 | 200,464 | 200,595 |
| 1 万重叠或不同幅值事件 | 200,100 | 200,231 |

- 所有基准场景的原生块和 pickle 内容 SHA-256 前后一致，不只是体积相同。
- int16、int32、非线性 int16、非线性＋SOS int16 均与基线逐点一致。
- DRAG float64 最大绝对差：重复模板 `1.67e-16`，不同模板 `3.33e-16`；来自向量三角函数。其他基准场景 float64 完全一致。不承诺向量 / 标量三角函数逐位相等。
- Linux 默认分派构建与禁用 AVX-512 的构建：各 **309 passed**。基线已有测试为 267 项；新增 42 项。
- macOS ARM64：**377 passed**，包括工作区原有未提交的额外测试。本次没有执行 Windows 或 GitHub Actions，不据 Linux AVX2 结果宣称 Windows 的性能倍率。
- 独立 C 测试强制运行所有可用量化和非线性内核：Linux AVX2 / AVX-512、macOS NEON 均通过。覆盖尾部、非对齐 SIMD 地址、端点、随机区间、原地映射、NaN/Inf、半 LSB 邻点及饱和。
- Linux ASan＋UBSan＋LeakSanitizer、macOS ASan＋UBSan 均通过。分配失败测试还覆盖 DRAG 多块求值中途失败后回退、整数模板暂存区分配失败及资源释放。

## 复现要点

在同一个 uv / Python 3.14 环境中独立构建基线和修改版。源码归档需先补齐相同 ANTLR 4.13.2 生成的 Lexer / Parser / Listener；与仓库 CI 的生成步骤一致。

```sh
# 每个源代码目录分别执行；不要让 CFLAGS 只剩 -D 宏而丢失 -O3。
/path/to/env/bin/python setup.py build_ext --inplace --force
/path/to/env/bin/python -m pytest -q

# 对两棵已构建源码树交替重复三轮，保存 JSON 和可比较的采样数组。
taskset -c 2 /path/to/env/bin/python benchmarks/benchmark_common_pipeline.py \
    --source-root /path/to/build --repeats 11 --samples-dir /path/to/samples

# 从同一版源码分别构建私有内核探针。
gcc -O3 -fPIC -shared -Iwaveforms benchmarks/simd_kernel_probe.c -lm -o /tmp/probe.so
taskset -c 2 /path/to/env/bin/python benchmarks/benchmark_simd_kernels.py \
    --source-root /path/to/build --library /tmp/probe.so

gcc -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer \
    tests/native_simd.c -lm -o /tmp/wf-simd-test
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 /tmp/wf-simd-test
```

`tests/native_common_pipeline.c` 使用同样的 sanitizer 参数。macOS 将 `-lm` 换为 `-framework Accelerate`，不使用 `taskset`。本组优化的发布版本为 3.6.1；本文数据来自升版前的实测。
