# 共性加载与采样优化（2026-09-08）

## 范围与方法

- 基线：`47c48de`，使用改动前独立复制的包及原生扩展；比较双方使用相同构建工具、解释器和现有 SIMD 设置。
- 环境：macOS-15.0-arm64-arm-64bit，Python 3.12.10，NumPy 2.3.1，Apple Clang 16。这里不是 8840U 的 Linux 实测。
- 采样率：2.4 GHz；接收端延时校准：2 ns；测试覆盖全部事件所在的时间范围。
- 按 A/B/B/A 顺序运行四个独立进程。每项每进程自适应循环、重复 9 次，取中位数；下表为两个进程中位数的均值。单位均为 ms；倍率为基线耗时 / 修改后耗时。
- 大数组分配和宿主机负载会影响绝对时间；原始两次进程中位数保存在 `common_pipeline_results.json`，不据此推断其他 CPU 的倍率。
- `cold_*` 每次从 pickle 创建新对象，然后 shift，再首次 sample，完整包含 native 解码和计划建立；`warm_*` 复用采样计划。

## 实现

1. WNS4 直接解码到最终数组；校验事件时同时统计支持范围，不再经过临时事件数组、第二次复制、重新编码。
2. 构造和加载栈时不再主动扫描整个块计算哈希。显式请求 C 栈哈希时才计算，并以原子操作缓存；哈希算法、返回值、Python 哈希和二进制格式均保持不变。普通采样从不需要这项工作。
3. 实数 waveform 和 stack 的无后处理采样可直接写入对齐、连续的 float64 `out`；包括没有原生 sample-plan 的有理数采样率回退。保留 dtype 转换、非连续、非本机字节序及非对齐输出的原语义，不进行自身复制。
4. 高模板数 sample-plan 使用临时 `(template ID, tick phase)` 哈希索引，避免每个事件线性扫描所有已有组；少数组继续走简单查找，重复单组保留快捷路径。分组创建和累加顺序不变，临时索引建完即释放。
5. 模板放置区间使用防溢出的整数裁剪，去掉这里的 long double 转换；没有更改波形求值坐标的 long double 计算或精度。

## 分阶段收益

| 场景 | 批量事件构造 | native 解码，不请求 hash | native 解码并请求 hash | 热采样，float64 out |
| --- | ---: | ---: | ---: | ---: |
| 1000 DRAG／重复模板 | 0.0340 → 0.0073（4.68×） | 0.0326 → 0.0045（7.31×） | 0.0324 → 0.0302（1.07×） | 0.0524 → 0.0321（1.63×） |
| 1000 DRAG／1000 个不同相位模板 | 0.9030 → 0.6758（1.34×） | 0.6280 → 0.3903（1.61×） | 0.6303 → 0.6154（1.02×） | 0.0774 → 0.0539（1.44×） |
| 1 万 CZ/iSWAP／密集 | 0.3186 → 0.0508（6.28×） | 0.3214 → 0.0402（7.99×） | 0.3253 → 0.3006（1.08×） | 1.2804 → 0.3488（3.67×） |
| 1 万 CZ/iSWAP／稀疏 | 0.3182 → 0.0505（6.30×） | 0.3436 → 0.0463（7.42×） | 0.3267 → 0.3302（0.99×） | 1.9416 → 0.8796（2.21×） |
| 1 万重叠事件 | 0.3194 → 0.0498（6.42×） | 0.3907 → 0.0456（8.57×） | 0.3553 → 0.3147（1.13×） | 0.3886 → 0.1966（1.98×） |
| 1 万事件／连续变化幅值 | 0.3188 → 0.0498（6.40×） | 0.3536 → 0.0407（8.68×） | 0.3501 → 0.3071（1.14×） | 1.0503 → 0.2710（3.88×） |

解码加速的大头是去掉本来采样不需要的哈希，而非声称内存复制本身快了 8 倍。`decode_and_hash` 单独列出这项成本：若调用方确实需要哈希，总耗时改进明显小得多。`pickle.loads` 原有的延迟解码机制未变，因此不以其单项速度代表端到端收益。

1000 个不同相位模板的计划建立：1.8269 → 1.6750（1.09×）。单模板计划基本不变，不声称所有场景的计划建立都有收益。

## 序列化与正确性

| 场景 | 原生块字节数（前后相同） | pickle 字节数（前后相同） |
| --- | ---: | ---: |
| 1000 DRAG／重复模板 | 20168 | 20290 |
| 1000 DRAG／1000 个不同相位模板 | 172016 | 172147 |
| 1 万 CZ/iSWAP／密集 | 200464 | 200595 |
| 1 万 CZ/iSWAP／稀疏 | 200464 | 200595 |
| 1 万重叠事件 | 200100 | 200231 |
| 1 万事件／连续变化幅值 | 200100 | 200231 |

- 四个对照进程中，全部场景的 float64、int16、int32 及非线性＋SOS＋int16 结果 SHA-256 一致。
- 完整 Python 测试：修改前 236 passed；修改后 335 passed。
- 新增覆盖：原生字节块所有权、损坏/截断布局、非有限事件幅值、并发首次哈希、空栈、输出边界、零幅值、重叠和乱序、多模板/多 tick 相位、各种输出缓冲区布局及类型转换。
- 独立 C 检查覆盖 INT64_MIN/MAX、SIZE_MAX 区间裁剪，逐字节损坏输入，以及逐次模拟 malloc/calloc/realloc 失败。macOS ASan＋UBSan 通过；LeakSanitizer 未启用。
- 本轮未执行 Linux/Windows 或 GitHub Actions；MSVC 的缓存使用 Interlocked，GCC/Clang 使用 atomic builtins。新增 Python 测试会随现有三平台测试矩阵运行。

## 未保留与未实施

- 尝试过只初始化非重叠事件之间的空隙，但部分稀疏栈出现明显性能回退，已撤销；保留原有完整初始化方式。
- 非线性＋SOS 后处理的热采样总耗时基本不变，本轮没有改动其内核或执行顺序。
- SIMD 分派、AVX2/AVX-512 内核、float32 非线性系数的运行时布局、完整流水线分块和采样坐标生成仍留待后续独立优化。
- 基准测试时保持原版本号；随后本次优化随 `3.6.0` 提交，不推送。没有修改工作区已有的 qlispc patch、notebook 和其他未提交文件。

## 复现

```sh
.venv/bin/python setup.py build_ext --inplace
.venv/bin/python -m pytest -q
.venv/bin/python benchmarks/benchmark_common_pipeline.py --source-root /path/to/baseline --repeats 9
.venv/bin/python benchmarks/benchmark_common_pipeline.py --source-root /path/to/current --repeats 9
clang -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer tests/native_common_pipeline.c -framework Accelerate -o /tmp/wf-common-test
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 /tmp/wf-common-test
```

独立 C 检查在 Linux 编译时将 `-framework Accelerate` 换成 `-lm`。
